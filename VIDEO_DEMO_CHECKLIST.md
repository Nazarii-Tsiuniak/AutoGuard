# AutoGuard: чекліст відеозахисту лабораторної №6

Ціль: показати 7 завдань і власний автомобільний функціонал за 12–15 хвилин. Результати перевірки: [LAB6_AUDIT_REPORT.md](LAB6_AUDIT_REPORT.md). Нижче сценарій для виконання людиною; позначки не означають, що ручні кроки вже виконано.

## Підготовка до запису

- [ ] Запустити актуальний AutoGuard: `.\.venv\Scripts\python run.py`, відкрити **http://127.0.0.1:5050**, оновити Ctrl+F5. Якщо треба, спершу зупинити тільки попередній сервер AutoGuard.
- [ ] Закрити вкладки `.env`, `secret_key`, `totp_encryption_key`, файли з токенами й паролями. На записі не показувати credentials, повний QR TOTP або одноразові URL.
- [ ] Створити окремий демонстраційний USER і окремого ADMIN, не використовувати основний акаунт для невдалих входів/зміни пароля.
- [ ] ADMIN підготувати через `flask --app run create-admin`; пароль вводити приховано. Перевірити вхід в іншому браузерному профілі.
- [ ] Відкрити Gmail для демонстраційної адреси, перевірити вхідні й «Спам». SMTP credentials не показувати. Локальний `.eml` не видавати за реальне отримання листа.
- [ ] Підготувати Google/Microsoft Authenticator на телефоні; синхронізувати час телефона.
- [ ] Налаштувати Google OIDC самостійно: consent screen, test user, client ID/secret у локальному `.env`, Redirect URI **http://127.0.0.1:5050/auth/google/callback**. Перезапустити сервер. Цей пункт ще не виконано під час аудиту.
- [ ] Перевірити CAPTCHA: локально використовуються офіційні dummy-ключі. Назвати це вголос. Для показу справжньої перевірки людини потрібен власний widget і дозволений домен.
- [ ] Перевірити сторінки на ширині приблизно 390, 768 і 1440 px: немає горизонтального переповнення, мобільне меню відкривається, поля й кнопки доступні. Цей візуальний QA під час аудиту не виконано через відсутність браузера.

## 1. Технології й головна — 45 секунд

- [ ] Відкрити `/` і коротко показати навігацію.
- [ ] Назвати Flask, SQLite/SQLAlchemy, Flask-Login/WTF/Limiter, Argon2id, PyOTP/Fernet, Authlib, SMTP і Turnstile.
- [ ] Показати структуру `autoguard/`, `tests/`, `migrations/` без runtime-секретів.

Очікується: застосунок працює локально на порту 5050, інтерфейс українською.

## 2. Реєстрація й пароль — 1 хвилина

- [ ] Відкрити `/auth/register`, ввести демонстраційне ім’я/email.
- [ ] Спробувати `weak`, потім пароль без цифри/спецсимволу.
- [ ] Показати індикатор і серверне повідомлення про вимоги.
- [ ] Ввести власний сильний демонстраційний пароль поза кадром.

Очікується: слабкий пароль відхилено, валідний пароль відповідає політиці. Паролі не зберігаються відкрито: можна показати код `PasswordHasher(type=Type.ID)`, не показувати робочу БД.

## 3. CAPTCHA й реєстрація — 1 хвилина

- [ ] Показати Turnstile widget і пройти його вручну.
- [ ] Зареєструвати демонстраційний USER.
- [ ] Пояснити, що сервер викликає Siteverify; без токена реєстрація не проходить.
- [ ] Якщо показуються dummy-ключі, прямо назвати тестовий режим. Не називати його доказом production-захисту від ботів.

Очікується: реєстрація оброблена, можна увійти й отримати лист активації. Кодові негативні сценарії показати у pytest, не вимикати CAPTCHA в застосунку.

## 4. Email і активація — 1–2 хвилини

- [ ] Увійти новим USER, відкрити `/profile`.
- [ ] Показати статус «Очікує підтвердження» та обмеження `/garage/`.
- [ ] Відкрити **реальний** лист у Gmail; токеновий URL приховати монтажем/кадруванням.
- [ ] Перейти за посиланням і підтвердити активацію кнопкою.
- [ ] Повернутися у профіль: «Підтверджено», гараж доступний.
- [ ] Повторний перехід за тим самим посиланням дає відмову. Прострочення краще підтвердити pytest, не редагувати робочу БД.

Очікується: випадковий токен одноразовий і має строк 30 хвилин. Якщо лист не приходить, перевірити «Спам» та повторне надсилання; повідомлення про SMTP-помилку тепер відображається в профілі.

## 5. Гараж, кілька робіт і витрати — 2 хвилини

- [ ] `/garage/new`: почати вводити марку, вибрати підказку; модель пропонується для марки. Показати також довільний ручний варіант.
- [ ] Рік і пробіг ввести вручну. Зберегти авто, потім відредагувати.
- [ ] На сторінці авто ввести дату `ДД.ММ.РРРР`, першу роботу з підказки.
- [ ] Натиснути **«Додати ще роботу»**, додати власну другу роботу. Зайвий рядок прибрати ×.
- [ ] Ввести пробіг і **загальну** суму, наприклад `1800,50`, зберегти один запис.
- [ ] Показати обидві роботи в історії. Відкрити «Редагувати», змінити одну роботу й суму, зберегти.
- [ ] `/statistics`: сума врахована один раз, є розподіл за місяцем та авто.
- [ ] На окремому другому USER показати, що чужий URL авто/ТО дає 404. Не використовувати реальні чужі дані.
- [ ] За потреби видалити тільки одноразові демонстраційні записи/авто, які створені для цього відео.

## 6. Brute Force та адміністратор — 2 хвилини

- [ ] Вийти з демонстраційного USER. П’ять разів ввести неправильний пароль саме цього USER.
- [ ] Ввести правильний — тимчасове обмеження залишається. Не продовжувати спроби безперервно: вікно ковзне.
- [ ] В іншому браузерному профілі увійти ADMIN, відкрити `/admin`, знайти USER.
- [ ] Показати статус активації, число невдалих спроб і `/admin/logins`: IP, UTC-час, результат.
- [ ] Заблокувати й розблокувати USER. Показати нові події, старі невдалі входи залишаються.
- [ ] Звичайним USER відкрити `/admin` — 403. Анонімно `/profile` — перехід на вхід.

Очікується: ліміти працюють на сервері; приховування кнопок не є єдиним захистом. Розблокування адміністратором скидає account lock, але окремий IP-limit може ще діяти; після 20 спроб за 15 хвилин слід дочекатися його спливу, не перезапускати сервер як «обхід» для ролика.

## 7. 2FA — 1–2 хвилини

- [ ] Увійти активованим демонстраційним USER, відкрити `/auth/security`.
- [ ] Натиснути «Налаштувати 2FA»; відсканувати QR поза кадром.
- [ ] Ввести свіжий код, увімкнути 2FA.
- [ ] Вийти, увійти паролем: має з’явитися `/auth/two-factor`.
- [ ] Неправильний код не дає доступу до `/dashboard`.
- [ ] Ввести **новий** код з Authenticator і показати успішний вхід.
- [ ] Пояснити, що код, уже використаний для підключення/входу, не можна повторювати; для наступного кроку дочекатися нового 30-секундного коду.
- [ ] Для вимкнення ввести поточний пароль і новий код. Не вимикати 2FA основного акаунта для ролика.

## 8. Google OpenID Connect — 1–2 хвилини

- [ ] Переконатися, що credentials налаштовані, UI більше не показує «Google ще не налаштовано».
- [ ] Для існуючого локального email спочатку локально увійти, у «Безпека» натиснути «Пов’язати Google-акаунт».
- [ ] Показати сторінку Google consent/account selection, завершити вхід дозволеним test user.
- [ ] Вийти, натиснути «Увійти через Google», завершити callback.
- [ ] Якщо локально ввімкнено 2FA, показати додаткову вимогу TOTP після Google.

Очікується: справжній зовнішній вхід, а не перехід на локальну заглушку. Якщо Google не налаштовано, цей пункт відео не готовий: mock JWT-тести не замінюють його демонстрацію.

## 9. Відновлення пароля — 1–2 хвилини

- [ ] Вийти, відкрити `/auth/forgot`, запросити відновлення демонстраційного USER.
- [ ] Показати **справжній Gmail-лист**, приховавши URL-токен.
- [ ] Перейти за посиланням, спробувати слабкий пароль: відмова.
- [ ] Встановити новий сильний пароль поза кадром. Попередня сесія в іншому браузерному профілі більше не відкриває гараж.
- [ ] Старий пароль відхиляється, новий працює; якщо ввімкнено 2FA, воно залишається обов’язковим.
- [ ] Повторне використання reset URL відхиляється.
- [ ] Для вигаданого невідомого email повідомлення таке саме. Не робити масових запитів — є rate limit.

- [ ] Коротко пояснити виправлення сесій, валідації TOTP/сум/CAPTCHA, SMTP-помилок і редагування ТО.
- [ ] Чесно відокремити mocks, файлову пошту та реальний SMTP/OIDC/CAPTCHA.
- [ ] Показати `.gitignore` і звіт аудиту, без відкриття `.env`.
- [ ] Назвати труднощі: Gmail app password, OIDC Redirect URI, одноразовість TOTP/токенів, розмежування доступу.
- [ ] Не виконувати git push або зміну публічного доступу під час ролика без окремого рішення.
