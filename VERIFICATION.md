# Перевірка AutoGuard

Оновлено: 23 жовтня 2026 року. Середовище: Windows, Python 3.13.7, окрема `.venv`. Детальний підсумок — у [LAB6_AUDIT_REPORT.md](LAB6_AUDIT_REPORT.md).

## Автоматизовано

- `python -m pytest -q --tb=short`: **90 тестів пройдено**.
- `python local_http_audit.py`: **23/23** через справжні HTTP-запити й CSRF на тимчасовій БД; Cloudflare Siteverify справді викликано з публічними dummy-ключами. Gmail-листів цей прогін не надсилає.
- `pip-audit`: після оновлення `cryptography` до 50.0.2 і `pip` до 26.2.2 — **No known vulnerabilities found**. JSON-звіти до/після збережено поряд із кодом.
- `python -m pip check`: конфліктів залежностей не виявлено.
- Початкова Alembic-міграція застосована до локальної SQLite.
- `flask --app run db check`: моделі й схема узгоджені, нових операцій немає.
- Локальний сервер Waitress: HTTP 200 для головної сторінки.
- Публічні сторінки входу, реєстрації, відновлення та локальний Bootstrap CSS повертають 200. Авторизовані сторінки перевірені Flask test client.

Тести охоплюють:

- Політику пароля, Argon2id і різну сіль, примусову роль USER при реєстрації.
- CAPTCHA: відсутній токен, відмова, timeout, production hostname/action.
- Активацію, строк токенів, призначення, одноразовість, відкликання попереднього токена й обмеження повторної пошти.
- Вхід/вихід, загальні повідомлення для невідомого email, між-IP блокування після 5 помилок та сплив 15-хвилинного вікна.
- Реальні обмежувачі IP-входу й TOTP (відповідь 429).
- RBAC, захист адміністратора, пошук, блокування, розблокування та відкликання сесій.
- Створення, редагування, видалення автомобілів, додавання/видалення ТО, оновлення пробігу, точні суми, статистику, валідацію полів.
- Ручне введення чисел і дати без number/date-контролів; декілька робіт в одному записі зі спільною датою та сумою без дублювання витрат, власні назви, кому у вартості, збереження введених робіт при помилці, ліміти та екранування XSS. Міграцію перевірено на старому записі зі збереженням суми, приміток, зв’язків і обмежень БД.
- IDOR: чужі авто, редагування, видалення та чужі записи ТО відхиляються; чужі дані відсутні в історії.
- Екранування XSS у примітках.
- Шифрування TOTP, QR, ввімкнення, проміжний вхід без повної сесії, відхилення повтору коду, вимкнення з підтвердженням, відкликання проміжної сесії.
- Скидання пароля: політика, одноразовість, подія аудиту, відкликання інших сесій і відмова старого пароля.
- CSRF: відсутній токен відхиляється, коректний токен дозволяє вхід та POST-вихід, GET-вихід відхиляється.
- Cookie HttpOnly/SameSite, CSP та відсутність секретних полів на сторінці адміністратора.
- Приховування токенів активації/скидання в повідомленнях Flask logger.
- CLI створення адміністратора, відхилення некоректного production-налаштування.

## Зовнішні інтеграції

Google: перевірено локальну поведінку застосунку з mocks та справжній код Authlib із локально підписаним RSA JWT. Мережева discovery/JWKS/token-відповідь підмінена. Перевірені PKCE, state, nonce, підпис, issuer, audience, expiry, email_verified та повтор callback. Окремо перевірено відмову автоматичного зв’язування за email, блокування та вимогу 2FA. **Реальний вхід у Google не виконувався.**

SMTP: mock перевіряє STARTTLS, авторизацію й формат листа. Файлова пошта перевірена в тимчасовій папці. Додатково реальні Gmail STARTTLS і авторизація пройшли успішно без надсилання нових листів. Користувач раніше підтвердив роботу листів. **Нове незалежне отримання листа в Inbox під час аудиту не перевірялося.**

Майстер `configure_gmail.py`: 4 тести перевіряють Gmail SMTP-параметри, нормалізацію пароля застосунку, збереження інших параметрів `.env`, повторний запис без дублювання та відмову від змін при некоректних даних. Credentials користувач уже ввів раніше, SMTP налаштований. Під час аудиту credentials не змінювалися.

Turnstile: негативні виклики Siteverify перевірені через mocks; позитивний шлях — додатково через справжній Siteverify у HTTP-прогоні з офіційними dummy-ключами. **Справжня CAPTCHA у браузері та production-ключі не перевірені.**

## Межі перевірки

У середовищі немає доступного браузера: інвентар браузерів порожній, створення in-app browser повертає `Browser is not available: iab`. Тому візуальна якість, мобільна адаптивність і повний браузерний сценарій вручну ще не перевірені. CSS містить адаптивні breakpoint-и, reduced-motion і доступну навігацію; це не замінює браузерну перевірку.

Production HTTPS, reverse proxy, Redis, реальна пошта, OAuth credentials, реальна Turnstile CAPTCHA та робота під навантаженням не перевірені. Тести не є незалежним аудитом безпеки.

Git-репозиторій у робочій папці відсутній; історії для сканування немає. Вихідні файли перевірені на очевидні секрети; runtime-ключі та БД залишені в ігнорованій `instance/`. Перед першою публікацією потрібна перевірка staged-файлів та історії, якщо вона з’явиться. Push не виконувався.
